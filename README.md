# Science Conferences

Платформа конференций на React и Vite с ASP.NET Core и PostgreSQL.

- **Dashboard**: календарь текущего месяца, переход по месяцам, карточки конференций и секций. Даты отображаются по Москве.
- **My Schedule**, **Venues**, **Settings**: сохранённые конференции, площадки и настройки профиля и уведомлений. Сохранённое расписание и настройки хранятся в этом браузере.
- **Личный профиль**: вход и регистрация по email с выбором роли. Идентификатор и роль сохраняются в localStorage. Участник может нажать «Стать организатором».
- **Конференции и секции**: организатор создаёт конференцию из календаря и добавляет секции в её карточке.
- **Подача доклада**: «Хочу стать спикером» в карточке конференции, с выбором секции.
- **Organizer**: все заявки, фильтры по статусу, принятие и отклонение. Комплектный сервер проверяет роль на GET и PATCH.

## Запуск через Docker

Нужен запущенный Docker Desktop или Docker Engine с Compose ≥ 2.17. Фронтенд и бэкенд должны лежать рядом:

```text
project/
  conf-frontend/
  conf-backend/
```

Используйте версию бэкенда с маршрутами auth и миграцией DashboardAuthAndTracks.
Расположение исходников можно изменить через BACKEND_CONTEXT в файле .env.

Для локальной проверки регистрация и смена роли доступны в интерфейсе. Настраивать .env для регистрации организатора не нужно. Необязательные переменные окружения описаны в .env.example.

```bash
docker compose up --build -d
```

Откройте http://localhost. В архиве START.cmd запускает отдельный проект на http://localhost:8082. Compose запускает PostgreSQL, применяет миграции отдельной задачей, запускает API и Nginx. Задача migrate завершается с кодом 0. База хранится в именованном томе. При остановке через docker compose down том сохраняется. При занятом порте 80 задайте FRONTEND_PORT=8081 в .env и откройте http://localhost:8081.

Если нужно проверить отдельную копию проекта, выполните в тестовой копии conf-frontend:

```bash
FRONTEND_PORT=8082 docker compose -p science-conferences-final up --build -d
```

Отдельное имя проекта даёт отдельный том PostgreSQL. Используйте другую копию каталога бэкенда, если требуется проверить другую ветку. При наличии общих образов уже запущенные контейнеры продолжают работать с теми образами, с которыми были созданы.

## Разработка через Vite

Запустите бэкенд по инструкции conf-backend на https://localhost:7239. Затем из conf-frontend:

```bash
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. Vite проксирует /api на локальный бэкенд. Фронтенд принимает ответ входа с полями userId, fullName, role; если сервер выдал access_token, он передаётся в Authorization и хранится в текущей вкладке. Другой адрес можно задать через API_PROXY_TARGET в .env.local. При контейнерном запуске /api проксирует Nginx.

## Проверка сценариев

1. Переключить месяц и открыть конференцию. В чистой базе демонстрационные конференции находятся в октябре 2026; кнопка «К месяцу событий» переносит к ним из пустого месяца.
2. В карточке посмотреть секции, подать доклад и увидеть уведомление об отправке.
3. Зарегистрировать участника. Нажать «Стать организатором», создать конференцию и добавить секцию.
4. Отправить заявку через «Хочу стать спикером». В Organizer принять или отклонить заявку: статус меняется на карточке и сохраняется после обновления.
5. Выйти и проверить регистрацию с ролью «Организатор».

```bash
npm run lint
npm run build
```
